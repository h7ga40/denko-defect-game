# Physical Inspection Model

更新日: 2026-07-20

## 目的

引張り、締付け、挿入、破損など、静止した正面SVGだけでは判定できない施工状態を、2D SVGと将来の3D表示で共通利用できるデータとして管理する。

現段階では3DモデルとThree.jsを導入しない。まずSVGの欠陥図と検査操作から利用し、問題生成と採点を特定レンダラーへ依存させない。

## データの分離

各`InspectionPart`は`PhysicalInspectionModel`を持つ。

- `expected`: 正常な完成状態
- `installed`: 出題用の施工結果
- `actions`: 状態を調べるために利用できる検査操作
- `PhysicalInspectionSession`: 画面上で選択した操作、視点、観察結果

欠陥名を直接SVGへ渡して見た目を決めるだけでなく、`expected`と`installed`の差を判定根拠にできる構造とする。

## 施工状態

`PhysicalTargetState`は部品全体、端子、ねじ、心線、ケーブル、カバー、接続材、電線管などの安定した対象IDごとに保持する。

- 締付け: 正常、緩み、未締付け、締め過ぎ
- 保持: 固定、がたつき、引張りで抜ける
- 挿入: 正常、不足、挿入し過ぎ、未挿入
- 圧着: 正常、未圧着、刻印欠け、複数刻印
- 組立: 正常、位置違い、不足、正常に閉じない
- 完全性: 正常、破損
- 接続: 正常、端子違い、未接続
- 寸法: 長さ、挿入深さ、心線露出、心線突出、シース剥ぎ長
- 破損: 種類、箇所、確認できる方向、長さ、深さ

数値基準が公式資料で定められていない状態へ、独自の締付けトルクや引張り力を設定しない。引張りは`inspection_pull`という検査操作と、その結果が保持または脱落のどちらかとして管理する。

## 検査操作

`InspectionAction`は次の判別可能な型で管理する。

- `view`: 正面、背面、左右、上下、自由視点から確認
- `pull`: 電線または器具を軽く引いて保持状態を確認
- `wiggle`: 固定部のがたつきを確認
- `remove_cover`: カバーを外して内部対象を表示

操作結果は`InspectionObservation`として、表示可否、保持・脱落、安定・がたつき、カバー取り外しを記録する。SVGでは表示切替や短いアニメーション、将来の3Dではカメラ・メッシュ・部品移動へ同じ操作を割り当てる。

## ID規約

物理対象IDは`InspectionPart.id`を基点にする。将来、1部品内に複数対象を持つ場合は次のように接尾辞を付ける。

- `device-sw1:terminal-0`
- `device-sw1:fastener-left`
- `device-lamp1:cover`
- `cable-part:cable-1:from-end`

SVG要素の`data-physical-target`と3Dメッシュの`userData.physicalTargetId`へ同じIDを設定できるようにする。

## 移行方針

1. 既存SVGは現在の`DefectType`描画を維持する
2. 新しい引張り・締付け・破損欠陥は物理施工状態から生成する
3. SVG用の共通`InspectionPartRenderer`で検査操作を受け取る
4. ランプレセプタクル1部品で操作と観察結果を検証する
5. 3D表示は同じモデルを読み取る別レンダラーとして追加する

採点はレンダラーの見た目やアニメーション結果から逆算せず、施工状態と観察結果から行う。
