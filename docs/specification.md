# Specification: 電気工事士2種技能試験ゲーム

## 1. 目的

第二種電気工事士技能試験の受験者が、候補問題の複線図、施工後チェック、部品ごとの欠陥をスマートフォンとPCで反復学習できるWebアプリを提供する。

## 2. 対象環境

- PCブラウザ
- Android Chromeを含むスマートフォンブラウザ
- GitHub Pagesによる静的ホスティング
- サーバーAPIやユーザー登録は使用しない

## 3. モード

ナビゲーション順と初期表示は、施工チェック、複線図、欠陥判定の順。初期モードは施工チェック。

### 用語方針

- 画面、問題文、支給部材では、一般財団法人電気技術者試験センターの受験案内、技能試験資料、欠陥の判断基準で使われる名称を優先する
- 複線図内は視認性を優先し、器具記号や省略表記を使用できる
- コード内のID（`push_connector` など）は既存データとの互換性を保つため変更しない
- 例: `差込形コネクタ`、`引掛シーリングローゼット`、`埋込連用タンブラスイッチ`、`埋込連用コンセント`

### 3.1 施工チェック

候補問題No.1～No.13から1問をランダムに選ぶ。

複線図上の選択対象:

- 直接選択: ランプ、引掛シーリングローゼット、スイッチ、コンセント、遮断器、端子台など
- ボックスとして選択: アウトレットボックス、ジョイントボックス
- candidateDiagrams.ts の connector はジョイントボックスとして扱う。箱本体は支給・施工されず、施工省略位置の配線と結線だけを扱う
- candidateDiagrams.ts の box はアウトレットボックスとして扱い、No.7右側・No.8・No.11・No.12右側の4か所だけに使用する

ボックスを選ぶと右側に配線図を表示する。ジョイントボックスは箱本体を描画・採点せず、施工省略位置を破線で示して配線と結線部だけを表示する。ジョイントボックスへ入るケーブルは、複線図上の相手部品との相対座標から侵入方向を求め、同じ相手へ向かう複数ケーブルは侵入口をずらして表示する。アウトレットボックスは正方形で表示し、各側面の19mm用・25mm用ノックアウト、開口済み穴、ゴムブッシングまたは管用ボックスコネクタを候補問題別データから描画する。ケーブルは指定された接続先の開口から侵入し、内側のシース端と心線の折曲点を経て、中央周辺のリングスリーブまたは差込形コネクタへ放射状に接続する。心線は実際の施工結果に従って連続表示し、誤結線では別の結線部へ到達し、未接続では結線手前で止まる。開口・ゴムブッシングは穴ごとに選択せず、ボックス外枠を選択して全体を一括判定する。No.11のE19とNo.12のPF管の点検部は下端へ分離して表示する。

出題ルール:

- ボックス内接続部と欠陥テンプレートを持つ直接選択器具から、合計2～3件を欠陥としてランダム設定
- リングスリーブは刻印不適合またはサイズ不適合
- 差込形コネクタは差し込み不足または接続本数不適合
- ボックス内接続は、正しい結線とは別に施工結果を保持し、心線の組合せ違いまたは未接続を出題
- 心線の組合せ違いは2つの結線間で心線を交換し、影響する両方を欠陥箇所として数える
- 未接続は正しい結線から心線を1本外し、結線手前で止まる遊び線として表示する
- ボックス・ブッシングは使用穴違い、取付忘れ、サイズ違い
- 金属管・PF管は管の挿入不足、絶縁ブッシングまたはロックナットの取付忘れ
- 直接選択器具は部品種別に応じて正常施工または既存の欠陥テンプレートを割り当てる
- タイムスイッチと自動点滅器は端子台形状と端子台の欠陥テンプレートで代用する
- 電動機と負荷器具は施工省略記号として表示するが、結線・選択・採点の対象にしない
- 蛍光灯は`fluorescent_lamp`として施工省略扱いにし、HOZAN記号を参考にした専用SVGを複線図だけへ表示する
- 屋外灯は`outdoor_light`として施工省略扱いにし、二重円形の専用SVGをNo.13の複線図だけへ表示する
- 複線図の略号は詳細表示で正式名称へ変換する
- 詳細SVGの配線は器具端子まで連続させ、未接続欠陥のみ意図的な間隔を設ける
- ランプレセプタクル、引掛シーリングローゼット、スイッチ、コンセントなどの器具端は片側だけを配線する
- 器具端の配線進入方向は、複線図で接続点・ボックスを優先した接続相手の相対座標から上下左右を決定する
- 配線用遮断器、漏電遮断器、端子台、タイムスイッチ、自動点滅器は入出力端子があるため両側配線を維持する
- 選択直後は答え合わせしない
- 完了ボタンで全設問をまとめて採点
- 未回答は不正解として結果に表示
- 欠陥ありとして回答した接続部を採点前から一覧表示
- 再出題時に候補問題、接続部テンプレート、欠陥位置を再抽選

### 3.2 複線図

- 公式番号対応の候補問題No.1～No.13を切り替えて表示
- HOZANの過去出題例を基にした電線・器具・接続材料の想定数量・長さを候補問題別に表示
- 想定値であり、本試験では数量・長さ・接続方法・器具仕様が変わる可能性を明記
- 使用要否・使用箇所は問題要素として表示しない
- SVGは学習用に簡略化した独自図
- 器具座標はHOZAN候補問題No.1～No.13の複線図を配置基準とし、電源、接続点、器具、取付枠、施工省略部の上下左右とまとまりを保つ
- 原図画像の複製ではなく、選択操作とモバイル表示に必要な間隔を確保した独自SVGとする
- ケーブル区間は CableRunSpecification の coreColors を使い、芯線ごとに色付きの平行線として表示
- ケーブル区間にはHOZANの過去出題例を基にした器具間寸法をmm単位で表示
- 標準色は2芯が黒・白、3芯が黒・白・赤、4芯が黒・白・赤・青。単芯IVは接続色を使用
- メーカー2D CADは外形寸法と端子・取付部の配置確認に限定し、CADを直接変換・同梱せず独自SVGとして作図
- 詳細SVGはDeviceDetailShape.tsxへ共通化し、正常施工と欠陥表示で同じ部品形状を使用
- 電源、器具、接続点、配線色、主要ラベルを表示

### 3.3 欠陥判定

- problems.ts に26問を定義
- 1問ずつ回答後に正誤と解説を表示
- 全問終了後に得点を表示
- 最高得点を denko-defect-game-best-score キーでlocalStorageへ保存
- 欠陥タイプごとのSVGコンポーネントを使用

## 4. データモデル

### candidateCableStocks.ts / candidateMaterials.ts

候補問題No.1～No.13の想定支給部材をカテゴリ別に管理する。HOZANの過去出題例を参考に、電線の長さ・本数、器具数量、接続・付属部材数量を登録する。公式確定値としては扱わず、使用要否・使用箇所は持たない。

電線は`candidateCableStocks.ts`の`candidateCableStocks`へ構造化し、種別、シース有無、導体径、芯数、芯線色、1本あたりの支給長、数量を数値で保持する。画面の支給部材文字列はこのデータから生成する。支給部材と加工後ケーブルの依存方向を分離するため、支給電線データは表示用部材データとは別ファイルに置く。

### candidateDiagrams.ts

CandidateDiagram、CandidateDevice、CandidateConnectionで候補問題、器具座標、接続を管理する。CandidateDeviceは処理分類のtypeと、記号・欠陥テンプレートを識別するvariantを分けて保持する。CandidateConnectionのidはボックス結線から参照する安定したケーブルID、cableは候補問題ごとに確定したケーブル種別・芯数・芯線色・寸法の上書きに使用する。

CandidateDeviceの`x`・`y`は720×390のviewBox上の座標とし、HOZAN複線図における相対配置を基準にする。埋込連用取付枠の構成器具は`mountingFrames`内へまとめ、施工省略器具は実器具に対応する記号で表示する。

CandidateDiagramの`boxWirings`には、ボックスごとの正しい結線を明示できる。`deviceId`で対象ボックスを指定し、結線グループごとに接続方法と`cableId`・`coreIndex`の組を列挙する。`coreIndex`は0始まりとする。

```ts
boxWirings: [{
  deviceId: "box",
  groups: [{
    id: "neutral-1",
    method: "push_connector",
    conductors: [
      { cableId: "power", coreIndex: 1 },
      { cableId: "lamp", coreIndex: 1 },
    ],
  }],
}]
```

`deviceWirings`には、端子台などの器具について端子IDと接続する心線を明示する。候補問題No.3のタイムスイッチ代用端子台は、S1へジョイントボックス2側の黒線、S2へジョイントボックス2側と引掛シーリングローゼット側の白線2本、L1へ引掛シーリングローゼット側の黒線を接続する。

候補問題No.4・5の100V／200V電源は6極端子台として管理し、`terminalBlock.poles`に上からの端子名と回路名、`deviceWirings`に各端子へ接続する心線を保持する。No.4はN（白）・L（黒）・T（黒）・S（白）・R（赤）・未使用、No.5はN（白）・L（黒）・L1（黒）・L2（赤）・E（緑）・未使用の順とする。複線図と選択後の詳細図は同じデータを参照する。

候補問題No.7は、左側ジョイントボックス～右側アウトレットボックス間をVVF 1.6mm 3心、右側アウトレットボックス～4路スイッチ間をVVF 1.6mm 2心2本、右側アウトレットボックス～右側3路スイッチ間をVVF 1.6mm 3心とする。右上のランプレセプタクルは施工省略として直接選択・採点対象から除外する。

候補問題No.6は、2つの引掛シーリングローゼットをどちらもジョイントボックス1へ接続する。

候補問題No.8は、電源～アウトレットボックスをVVR 2.0mm 2心とする。配線用遮断器3台は6極端子台で代用し、端子1–2、3–4、5–6からアウトレットボックスへVVF 1.6mm 2心を各1本、合計3本接続する。6極端子台は各極に左右2端子がある計12端子として描画し、ケーブルが出る右列を施工、左列を施工省略として表示する。

候補問題No.13の自動点滅器代用端子台は左から1・2・3とする。1へジョイントボックス2側の黒線、2へジョイントボックス2側と屋外灯側の白線2本、3へ屋外灯側の黒線を接続する。

候補問題No.5は、ジョイントボックスから取付枠内のスイッチ群と埋込連用コンセントへVVF 1.6mm 2心を1本ずつ、合計2本接続する。取付枠の`jumpers`にはイ・ロ間の黒線または白線を許容する渡り線と、ロ・コンセント間の黒線渡りを保持する。現在の複線図は両方とも黒線で表示する。

### cableSpecifications.ts

複線図の論理接続から、作業対象となる物理ケーブル区間を`CableRunSpecification`として生成する。

- `cableType`: VVF、VVR、EM-EEF、IV
- `hasSheath`: 保護被覆（シース）の有無
- `conductorDiameterMm`: 1.6mmまたは2.0mm
- `coreCount`: 1～4芯
- `coreColors`: 各芯線の色
- `diagramLengthMm`: HOZAN想定図の器具間寸法
- `lengthMm`: 接続・器具側の余長を含む切断後のケーブル長
- `sourceStockId`: 切り出し元となる支給電線ID
- `sourceStockPieceIndex`: 同じ支給電線が複数本ある場合の0始まりの本数位置
- `fromEnd`／`toEnd`: 両端それぞれのシース剥ぎ長と、芯線ごとの絶縁被覆ストリップ長
- `measurementSource`: 指定値か推定値か

同じ`sourceStockId`を複数のケーブル区間から参照して、支給電線1本から複数区間を切り出す1対N関係を表現する。支給部材に記載された未加工電線の総延長、複線図の器具間寸法、切断後の各ケーブル長は別の値として管理する。支給部材画面では問題要素を伏せるため、この使用先関係を表示しない。

切断長はHOZANの施工寸法一覧に従い、「接続に必要な寸法 + 複線図の寸法 + 器具の結線に必要な寸法」で算出する。ボックス・接続点は100mm、埋込器具は100mm、ランプレセプタクルは50mmを加え、引掛シーリングローゼット、配線用遮断器、端子台はHOZANの解説と同様に追加分を含めない。候補問題の未公開施工条件を補う練習用想定値であり、公式確定値として扱わない。

長さ・剥ぎ取り寸法が施工条件や切断計画から確定していない場合は、誤った推測値を入れず`null`とする。`validateCandidateCableStockUsage()`は支給電線ID、電線仕様、本数位置、切断長合計が支給範囲内かを検証する。

ラベルにVVF 2.0-3C、VVR 1.6-2C、E1.6などがある場合は種別・導体径・芯数を推定する。緑指定の接地線は単芯IV、三相電源・電動機を含む経路は3芯として補完する。明示ラベルがない区間は暫定値を生成できるが、候補問題ごとの施工条件が判明した時点でCandidateConnectionの`cable`から上書きする。

`StrippedCableEnd.tsx`はケーブル端をシース、絶縁被覆、裸導体の3区間に分けて描画する。シース端は`sheathStripLengthMm`、芯線ごとの裸導体長は`insulationStripLengthsMm`から算出する。未確定値は表示専用の標準寸法へフォールバックするが、元データの`null`は変更しない。

### boxWiringSpecifications.ts

ボックス端の物理的な心線と正しい結線関係を管理する。

- `BoxConductorEndpoint`: ケーブルID、端部、芯番号、線色、導体径、用途、正しい結線ID
- `BoxConnectionGroup`: 結線ID、リングスリーブ／差込形コネクタ、所属する心線ID
- `BoxWiringSpecification`: ボックス内のケーブル、加工寸法、全心線、全結線グループ、データ由来
- `BoxWiringInstallation`: 心線IDごとの実際の接続先`actualConnectionIds`
- `correctConnectionId`が`null`の心線は、ボックス内で他の心線と接続しない
- `source`は候補問題に明示された`specified`か、簡略複線図から生成した`inferred`
- 接地線と判断できる緑線以外の`role`は、簡略複線図だけで断定せず`unassigned`とする

`boxWirings`が未定義の場合は、ボックスへ入るケーブルの同じ芯位置を暫定的に同じ結線グループとして推定する。5本以上になる場合は各グループが2～4本になるよう分割し、1本だけの芯は未接続として保持する。現在の候補問題No.1～No.13はこの推定値であり、公式施工条件の確認後に`boxWirings`へ明示値を入れる。

検証処理は、結線IDの重複、存在しない心線参照、心線の複数結線への重複所属、2～4本以外の接続、`correctConnectionId`との不一致をエラーにする。

施工結果は`createCorrectBoxWiringInstallation()`で正しい状態から生成する。未接続欠陥は`disconnectConductor()`、誤結線は`swapConductorConnections()`で施工結果だけを変更し、正しい結線データは変更しない。採点後の解説では、入れ替わった心線または未接続心線の接続元と線色を表示する。


### deviceSpecifications.ts

器具ごとの端子仕様を `DeviceVariant` 単位で一元管理する。端子数は電気的に同一な接続点を「端子グループ」として数え、同じ端子に複数ある差込口は `insertionHoles` で別に保持する。

| 器具 | 端子グループ数 | 接続口数／心線容量 | 備考 |
| --- | ---: | ---: | --- |
| ランプレセプタクル | 2 | 2 | 中心接点・受金 |
| 引掛シーリングローゼット | 2 | 2 | 非接地側・接地側 |
| 埋込連用パイロットランプ | 2 | 4 | 各端子2口 |
| 埋込連用タンブラスイッチ（片切／3路／4路） | 2／3／4 | 4／6／8 | 各端子2口、3路は0・1・3 |
| 埋込連用タンブラスイッチ群 | 6 | 12 | 3個の片切スイッチ相当 |
| 露出形コンセント | 2 | 2 | ねじ端子 |
| 埋込コンセント（接地極付／20A 250V 接地極付） | 3 | 5 | 2極は各2口、接地系統は1口 |
| 埋込コンセント（接地極付接地端子付） | 3 | 5 | L・N・E。接地極と接地端子は同じ接地系統 |
| 配線用／漏電遮断器 | 4 | 4 | 電源側2・負荷側2 |
| タイムスイッチ代用端子台 | 3 | 4心線 | S1・S2・L1を使用。S2へ2心線 |
| 6P端子台 | 6 | 12（各極2端子） | 候補問題ごとの使用端子はdeviceWiringsで指定 |
| 自動点滅器代用端子台 | 3 | 4心線 | 1・2・3を使用。2へ白線2本 |
| 接地端子 | 1 | 1 | 現在は直接選択対象外 |
| 電動機・負荷・施工省略 | 0 | 0 | 結線・採点対象外 |

`insertionHoles`は物理的な差込口数、`maxConductors`は1端子へ接続できる心線数を表す。ねじ端子では差込口が1か所でも複数心線を接続できる場合があり、候補問題No.3のS2端子とNo.13の2端子は`insertionHoles: 1`、`maxConductors: 2`とする。

`requiresWiring` は作業シミュレーションで結線対象にするか、`inspectionSelectable` は現在の施工チェックで直接選択できるかを表す。候補問題ごとに実際に使用する端子番号・渡り線・接続先は、器具固有の端子仕様とは分けて`CandidateDiagram.deviceWirings`へ定義する。

### boxInspectionGame.ts

- InspectionBox: 複線図上のボックスと内部接続部
- InspectionBox.wiring: 未接続心線を含むボックス全体の正しい接続関係
- InspectionBox.installation: 欠陥を反映した実際の施工結果
- BoxInspectionPart: ボックス内の設問、選択肢、正解、解説
- DirectInspectionPart: 複線図から直接選ぶ器具の設問。器具端のケーブル進入方向を cableEntrySide で保持
- BoxInspectionRound: 候補問題、ボックス、直接選択器具、全採点対象、欠陥数
- createBoxInspectionRound(): ラウンド生成とランダム化

各BoxInspectionPartのConnectionSpecは、`BoxConnectionGroup`に所属する心線だけを参照する。同じ心線を複数の設問へ重複生成しない。線色、太さ、ケーブル加工寸法、スリーブ・コネクタ仕様は所属心線から導出する。

各ラウンドには接続ミスを最低1件含める。誤結線は移動元・移動先の2件、未接続は1件として扱い、既存欠陥と合わせた欠陥箇所数を2～3件にする。

### problems.ts

DefectType、Problem、欠陥判定モードの全28問を管理する。

### 埋込連用取付枠

`CandidateDiagram.mountingFrames`で取付枠の座標と、上・中・下の各位置へ取り付ける器具を管理する。器具は`sourceDeviceId`で既存の複線図器具と関連付けでき、関連付けた器具の配線終端は取付枠内の該当位置へ移動する。No.2は上段パイロットランプ・下段スイッチ、No.10は上段パイロットランプ・中段スイッチ・下段コンセントとする。No.3・13は接地極付コンセント側に取付枠を配置する。

取付枠内の器具間渡り線は`jumpers`で接続元・接続先のメンバーID、表示色、許容色を管理する。複線図と取付枠詳細図は同じデータから渡り線を描画する。

施工チェックでは取付枠全体と枠内の各器具をそれぞれ回答対象にする。取付枠の詳細画面には器具切替ボタンを表示し、小さい画面でも各器具を選択できるようにする。`mounting_frame_loose`は固定不良、`mounting_frame_wrong_position`は上・中・下の位置違い、`pilot_lamp_wrong_terminal`はパイロットランプの端子接続違いとして出題する。

## 6. 操作・表示要件

- モバイルは1カラム、PCは施工チェックを2カラム表示
- SVGはviewBoxで画面幅へ追従
- 複線図内は部品略号、施工チェックと欠陥判定の詳細表示は正式名称を使用
- 部品本体を選択し、選択中・回答済み・正解・不正解は部品の輪郭色と状態マーカーで表示
- 埋込連用取付枠は枠全体と内部器具を個別選択し、構成・取付位置・器具ごとの施工状態を判定
- 部品の背面に透明なタップ領域を置き、SVG文字や装飾はpointer-eventsを無効化する
- キーボードのEnter／Spaceでも部品を選択できる
- 選択肢はPCで2列、狭い画面で1列

### 6.1 URLクエリー

- candidate: 1～13の候補問題番号。施工チェックと複線図の初期表示へ適用
- seed: 空でない任意文字列。候補抽選、欠陥数、欠陥位置、欠陥種類、接続ミス対象の乱数を固定
- candidateのみ指定した場合は候補番号を固定し、再出題では欠陥内容を再抽選
- seedを指定した場合は再出題でも同じラウンドを生成
- 同じアプリ版・candidate・seedの組合せで再現性を保証する。データまたは生成アルゴリズム変更後の版との互換性は保証しない
- 範囲外のcandidateと空のseedは無視する

例: ?candidate=5&seed=sample-2026
