# Current Status

更新日: 2026-07-20

## 現在の目標

当面は、候補問題の工作物が完成した後に欠陥を探す「施工チェックゲーム」を完成させる。

最終的には、支給部材の確認、複線図の作成、電線加工、器具への結線、ボックス内接続、完成確認までを順番に操作できる作業シミュレーションへ拡張する。

## 部品データの管理

CandidateDeviceは、処理上の大分類をtype、具体的な部品記号をvariantで管理する。

主なvariant:

- ランプレセプタクル、引掛シーリングローゼット、確認表示灯
- 片切、3路、4路、複合スイッチ
- 露出形、接地極付、20A接地極付、EETコンセント
- 配線用遮断器、漏電遮断器
- タイムスイッチ、自動点滅器
- 端子台、接地端子、電動機端子

リングスリーブと差込形コネクタは複線図から直接選ばず、ジョイントボックスまたはアウトレットボックスの内部で選択する。

## 選択と採点

- 旧来の破線選択枠は廃止
- 部品本体の輪郭色と状態マーカーで選択状態を表示
- Androidで押しやすいよう、部品の背面に透明なタップ領域を配置
- 選択直後には正誤を表示しない
- 回答済み、選択中、正解、不正解を別状態として保持
- 施工省略部、電動機、負荷器具は直接選択の出題対象から除外

## 現在の制約

- 複線図は公式図そのものではなく、アプリ用の学習用簡略図
- HOZAN図とは記号寸法や配線経路を完全一致させず、部品の上下左右と接続関係を保った独自SVGとして表示する
- 支給部材の数量・長さは過去出題例を基にした想定値であり、本試験では変更される可能性がある
- 支給部材の使用要否・使用箇所は原則として未表示。ただしNo.7・8・11・12のゴムブッシングと管用コネクタは、開口データに基づいて使用位置を表示する
- 候補問題No.1～No.13のボックス内結線はHOZAN結線図を基準に`boxWirings`へ明示入力済み
- アウトレットボックスは候補別の開口データ、ジョイントボックスは複線図上の相手部品との相対座標に基づいてケーブル侵入位置を決める
- 器具間寸法と切断長はHOZANの過去出題例に基づく想定値であり、当日の施工条件では変わる可能性がある
- タイムスイッチと自動点滅器は端子台形状・端子台欠陥テンプレートで代用する
- 電動機と負荷器具は施工省略記号として複線図だけに表示し、選択・結線・採点の対象外とする
- Android Chromeで候補問題No.1～No.13の実機回帰確認が必要
- 取付枠内の未関連器具は構成と位置を表示するが、個別の端子結線は今後の候補問題別`deviceWirings`整備対象
- 施工チェックの進行状態は再読み込みでリセットされる

## 欠陥実装監査（2026-07-20）

`_Ref/欠陥一覧.md`は42部材、約483項目を列挙している。同種の欠陥が電線・器具の種類ごとに重複しているため、コードでは共通する欠陥機構を`DefectType`へ集約して管理する。

施工チェックへ実装済み:

- ボックス内の誤結線と心線未接続
- リングスリーブの刻印違い・サイズ違い
- 差込形コネクタの挿入不足・極数不適合
- ランプレセプタクル、引掛シーリングローゼット、コンセントの極性・接地・輪作り・外装処理
- スイッチ、パイロットランプ、端子台の端子違いと遮断器の電源側・負荷側違い
- 埋込連用取付枠の位置違い・固定不良
- アウトレットボックスの使用穴、ゴムブッシング、金属管、PF管と付属品

修正が必要:

- リングスリーブのサイズ違いを、正しいサイズと実際に使用した誤サイズの双方が分かる表示にする
- 差込形コネクタの極数不適合を、単なる空き穴ではなく必要心線数との不一致として表す
- スイッチ・端子台の端子違いを、共通簡略図ではなく候補問題の正しい接続グラフから生成する
- ボックス内結線の第3段階をボックス全体図から部品単体図へ分離する
- ケーブル外装処理を候補問題別の加工寸法と連動させる

未実装だが既存データを利用して短期対応可能:

- リングスリーブの心線差し込み不足・絶縁被覆かみ込み
- リングスリーブの未圧着、圧着マーク欠け・二重刻印、心線突出
- 差込形コネクタの心線露出・挿入し過ぎ
- 施工条件とリングスリーブ・差込形コネクタの接続方法違い
- アウトレットボックスの余分な開口、管・コネクタの種類違い

仕様設計を先に見直す欠陥:

- ケーブル種類・配線場所・長さ・不要接続と、外装・絶縁被覆・心線の損傷
- 器具種類・配置の取り違え
- 引張りで抜ける、ねじ締付不足、カバー不良など外観だけで確定できない状態
- 管内電線数、管途中接続、ボンディング線
- 将来の3D表示で扱う破損、締付け、挿入深さなどの形状・隠れた欠陥

物理施工状態と検査操作の共通型は`docs/physical_inspection.md`に定義済み。次はSVGで操作と観察結果を扱う共通レンダラーを追加し、ランプレセプタクルを最初の対象として検証する。

実装順序としていた、既存リングスリーブ欠陥の統合、結線部品の単体表示、端子違いの接続グラフ連動、圧着・挿入欠陥の拡張、ケーブルの点検対象化までは完了した。

## 作業シミュレーションへの拡張案

完成後の欠陥探しを安定させてから、次の段階で実装する。

1. 支給部材の確認と使用部材の選択
2. 単線図から複線図への変換
3. ケーブル種類、長さ、芯線の選択
4. 外装・絶縁被覆の剥ぎ取り
5. 器具端子への結線と極性確認
6. リングスリーブまたは差込形コネクタによる接続
7. ボックス、連用取付枠、器具の組み立て
8. 完成品の自己点検と採点

作業シミュレーションでは、操作履歴を工程データとして保存し、最終形だけでなく途中の誤操作からも欠陥を判定できる設計が必要になる。現在のtype、variant、DefectTypeは、その工程データから完成状態を生成する際にも再利用する。
